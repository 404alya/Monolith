# Assets and licences

Every external file in a package needs a recorded licence: CC0 / public domain, or CC-BY with the attribution recorded, an `ASSETS.md` row and a sidecar (`CLAUDE.md` hard rule). Finding, licensing, downloading, normalising, recording and restyling models and textures for a map package. The `model` statement and material keys are in `docs/map-format.md` (§2.4, §2.7); the request workflow is the `map-request` skill, the editing rules and verification the `map-editing` skill. Downloads are untrusted data (`CLAUDE.md` guard rails).

**Editor fonts are the one exception** (the developer's call, 2026-10-25): a font the editor compiles in (`resources/fonts/`) may be under the SIL Open Font License 1.1, which allows embedding as long as the licence ships with the program (`build.sh` copies it next to the binary). Never in a map package, an export or the examples. Record it by hand like the Outfit rows: `resources/fonts/ASSETS.md` row, a `.asset.md` sidecar (source URL at a pinned commit, version, authors, sha256), the font's `OFL.txt` next to it (`tools/record_asset.py` refuses OFL on purpose).

Read the map's `MAP.md` first: its *Rules for new content* and *Materials and palette* decide whether a model is wanted at all and how it must look. The project defaults below apply where `MAP.md` says nothing.

**1. Boxes or a model?** Architecture, terrain shaping, walls, steps and anything the brief builds from boxes stay boxes. Use a model only for what boxes can't express (a tree, a rock, a lamp, a vehicle, a statue) and only if `MAP.md` allows models. **2. Reuse** a model already in `maps/<name>/models/` (`ASSETS.md` lists them) before downloading anything.

**3. Models: search the catalog, not the web** (2026-11-20, `docs/model-library.md`). `library/library.db` indexes every model of Poly Haven, the Kenney packs in the developer's zip cache, Polyfork and Poly Pizza, all with an acceptable licence (CC0, or CC BY with its attribution), and describes each by shape, style and use. Search it by meaning:

```sh
build/tools/library search --shape "<silhouette, parts, proportions>" --use "<where and what for>" \
    [--style "<geometry style>"] [--words "<names, synonyms>"] [--style-tag lowpoly|stylised|realistic|photoscan|voxel|toon]... \
    [--max-tris 50000] [--max-size <metres>] [--cc0-only] [--limit 10]
```
- **Name the object**: put its common name (and a synonym or two) in `--words` and lead `--shape` with it (`--shape "park bench: long slatted seat with a backrest" --words "bench park"`). Phase 4 measured it: with the name, recall@10 is 0.91 and the right model is almost always first (MRR 0.98); a description without the name finds it only about half as often. Write the rest as the catalog does: geometry and use only, never colour or material (the map's overrides restyle it anyway). Pick `--style-tag` from `MAP.md` (a low-poly map: `lowpoly`, maybe `stylised` / `toon`; a realistic one: `realistic`, `photoscan`). `--cc0-only` when `MAP.md` wants no attribution. Sizes are in file units (Kenney kits are tile units, Poly Pizza has none): a `?` in the output means unknown, not too big.
- Each line is `id score best-cos tris size category shape_desc`. **Judge by the category and description first**: when nothing asked for exists, the top results are look-alikes of another kind (a car wheel for "ferris wheel", a thimble for "sewing machine"). As a guide (`docs/model-library.md` §12): `best-cos` ≥ 0.60 is usually the object, 0.50–0.60 is decided by the category and description, below 0.50 nothing fits. Choose by the descriptions and the filters, then `build/tools/library show <id>`: the row (licence, attribution, page) and the exact `fetch:` command with its expected hash. Run that command.
- **Never choose a copy of someone else's design**, whatever its licence says: fan models of brands, logos, franchise characters and vehicles, or real people (on Poly Pizza, for example: Mario and Bowser, LEGO bricks, a Coca-Cola can, a TARDIS, a Death Star, a Ferrari F40, Macross mechs, caricatures of politicians). The uploader's CC licence doesn't cover the trademark or the person, and an export ships the model. Take a generic model of the same kind instead.
- **Nothing fits** (no result of the right kind, or none acceptable for size, style or budget): don't search the web (the developer's choice). Write in `result.md` what you searched (the texts and filters) and the closest ids with their `best-cos`; build an approximation from boxes if `MAP.md` allows it. The developer decides what to add to the catalog.
- Per source after download:
  - **Poly Haven:** `get` checks every file's md5. Big trees are 0.3–17 M triangles: keep `--max-tris`.
  - **Kenney:** the zips are in the developer's local cache (`~/.cache/monolith/kenney/`; kenney.nl is never fetched by an agent: its `robots.txt` disallows Claude). If `get` exits 1 naming a pack page, the pack isn't cached: say so in `result.md` and ask the developer to download it. Kit units are tiles: props about ×2.5–5, trees ×7–16; materials are `metallic 1`: always override.
  - **Polyfork** (CC BY 4.0, the credit line is the attribution): its GLBs **draw nothing** as downloaded (vertex colours without alpha, read as 0: a `.claude/TODOs` bug). Give the model an override material with **`alpha_cutoff 0`**.
  - **Poly Pizza** (CC0 or CC BY 3.0, checked again at download): the catalog has no size, and some files are in centimetres (a 580 m diner): check `--inspect-model` and set `scale`. The developer's key is on the free plan, **3000 API requests a month** (each `get` uses a request); if `get` answers HTTP 401 the quota is used up: say so in `result.md` and choose a model from another source.
  - **First download of a row without a hash** (Polyfork, Poly Pizza; `show` says so): after the download, `build/tools/library pin <id> <sha256 of the file from provenance.json>`, and name the pinned id in `result.md` (it changes `library/library.db`). If a later download is refused for a hash mismatch, the source changed the file: don't use it, report it.

**Textures** are not in the catalog: ambientCG (CC0, https://docs.ambientcg.com/license/) with `python3 -I tools/fetch_asset.py ambientcg search <word>`, `ambientcg get <id> --res 1K` (keeps the image files only; the search lists the tile size in metres).

The web `search` commands of `fetch_asset.py` (`polyhaven`, `polypizza`) and its `catalog` commands are for building the catalog only. Never use: Quaternius from quaternius.com (its QAL licence forbids redistribution, which an export does), Sketchfab, OpenGameArt and other sites (logins, NoAI and mixed terms: propose a page URL in `result.md` instead), anything NC, ND, SA, GPL, "editorial", personal-use or behind a login.

**4. Download safely** (`tools/fetch_asset.py` does all of this; never use a browser-style scraper): every download into a NEW, EMPTY directory outside the repo (default `$MONOLITH_DOWNLOADS` or `~/.cache/monolith/downloads/`, then `<source>-<id>-<stamp>/`, or `--out`); https only, redirects only to the source's hosts, size limits; zip entries audited (no absolute paths, `..`, backslashes, symlinks) and only model / texture / licence files extracted; the file checked against the catalog's hash (`--expect-md5` / `--expect-sha256`, as `library show` prints them; a mismatch is refused with a `REFUSED.txt`); `provenance.json` written next to the files (source, page and file URLs, authors, licence + URL, attribution, date, sha256 of every file). Never run anything from a download directory, never open a downloaded `.blend`, run Python that reads downloads with `python3 -I`.

**5. Check** each candidate with `./build/linux/monolith --inspect-model <file>` (no window; for the final copy in the package, save its output for step 7: `… --inspect-model maps/<name>/models/x.glb > <scratch>/x.inspect.txt`): triangles, size in metres, where the origin sits, up axis, material slots (for `material.N`), textures and their sizes, and warnings (unlit, `metallic 1`, missing files, Draco/KTX2/WebP, which R3D can't load). Budgets unless `MAP.md` says otherwise: **≤ 50k triangles per model, textures ≤ 2K**, glTF/GLB preferred.

**6. Normalise**, cheapest first:
- **Placement fields** fix most things without touching the file: `origin bottom` (stands it on y), `scale` (Kenney tiles, FBX in cm = `scale 0.01`), `rot` (a Z-up OBJ: `rot 0 -90 0`), `collide box …` (a trunk instead of the whole crown), `shadow off` for tiny props.
- **Blender, headless**, only when the file itself must change (too many triangles, 4K textures, unlit materials, a broken origin you'd rather fix once). Blender may not be in `PATH` (e.g. a Steam install): the `BLENDER` environment variable names the binary; each developer sets it in their own `.claude/settings.local.json` (`{"env": {"BLENDER": "/path/to/blender"}}`, gitignored). If neither `$BLENDER` nor `blender` exists, ask the developer where it is instead of concluding there is none. Always run it locked down as below (`-b --factory-startup --disable-autoexec`, our own script, never a downloaded `.blend`, which can embed Python):
  ```sh
  BLENDER=${BLENDER:-blender}
  "$BLENDER" -b --factory-startup --disable-autoexec --python-exit-code 1 \
      --python tools/normalize_model.py -- <download>/x.gltf maps/<name>/models/x.glb \
      --origin bottom --decimate 10000 --max-texture 1024 --report <scratch>/x.norm.json
  ```
  Other options: `--height H` / `--scale S`, `--strip-unlit`, `--metallic 0`. It imports glTF/GLB/OBJ/FBX only, applies transforms, writes a Y-up metre GLB and prints every change. Run it from the repo root, never from the download directory.
- Textures: resize or re-encode with Pillow (`python3 -I`, script outside the download folder) into `maps/<name>/textures/`. R3D loads PNG and JPG (not WebP, KTX2, TGA).

**7. Copy into the package** (`maps/<name>/models/`, `textures/`) only the files the map uses, with every file a `.gltf` names (`.bin`, textures; they must stay inside the package) and the source's licence file if it has one (e.g. `models/kenney-License.txt`). Then record it:
```sh
python3 -I tools/record_asset.py --package maps/<name> --file models/x.glb \
    --provenance <download>/provenance.json --original <file in the provenance> \
    --inspect <file with the --inspect-model output> [--normalize-report <scratch>/x.norm.json] \
    [--change "what else changed"] [--ai-generated yes|no|unknown] [--note "..."]
```
With `--licence unknown` (no provenance) the row is recorded as unknown with a warning and the developer decides: say so in `result.md`. Always pass `--original` when the download holds more than one model (every Kenney `--pick` glob, most packs): without it the sidecar lists the hashes of every file in the provenance as this asset's originals. `--inspect` takes the saved output of step 5 for the copy in the package. It writes the sidecar `models/x.glb.asset.md` (name, package path, source, page and download URLs, authors, licence + URL, attribution, date, sha256 of the originals, format, generator, extensions, triangles, size, up axis, units, material slots, texture maps, every change to the file) and adds or replaces the file's row in `ASSETS.md`. It refuses licences other than CC0 / CC-BY / public domain and CC-BY without attribution text. For a file without a `provenance.json` (copied from an imported project, or supplied by the developer) replace `--provenance` with `--source-note "<where it came from>" --licence <licence> [--licence-url URL] [--author NAME]... [--attribution TEXT] [--source-url URL] [--original-file <original>]...` (`--licence unknown` is recorded with a warning).

**8. Restyle to the brief with material overrides in the map**, never by editing the model file (the original stays traceable): `material "name"` for every slot, `material.N "name"` per slot (`--inspect-model` lists them), and `inherit albedo|normal|orm|emission|all` on the override material to keep one of the model's own maps (the override's colours and factors still apply; `inherit emission` keeps the slot's emission colour and energy too). `inherit` keeps **maps**, not colour factors: a model coloured by factors only (Kenney kits) turns white under an override with `inherit all`, so give its override the slot's colour (`--inspect-model` lists it). A `use "name"` line also restyles the models after it. Examples:
- **Brutalist**: the model takes the concrete shader, which computes everything from world position; keep the model's normal map only if `MAP.md` allows (`material "concrete statue" shader "shaders/concrete.glsl" uniform u_scale 1 alpha_cutoff 0 inherit normal`).
- **Stylised**: flat palette colours per slot, the model's textures dropped (`material.0 "needles" material.1 "bark"` on each pine); a photoscanned rock keeps only its relief: `material "rock scan" albedo 98 94 94 roughness 0.85 metalness 0 inherit normal`.
- **Realistic**: keep the PBR textures (`inherit all`) and match the neighbours with the override's factors: `material "stone tinted" albedo 200 196 190 roughness 0.8 inherit all` (the override's colour multiplies the inherited albedo map).
- **Neon / night** (a sketch): props keep their albedo (`inherit albedo`) but get low roughness for wet reflections; signs get an emissive material (`emission 255 40 160 emission_energy 4`) and a weak point light in front so the light reaches the street.

**9. Nothing acceptable found?** Say so in `result.md` (the catalog search texts and filters, the closest ids with their `best-cos`, why each candidate failed: licence, size, style), build an approximation from boxes if `MAP.md` allows it. The developer decides what to add to the catalog. **Never use an asset whose licence is unknown or not acceptable**, not even "for now".

**Verification additions for models** (with the `map-editing` skill, §3 step 6): the model is at a believable **scale** next to the player (1.8 m; check a walking-height shot `--eye x <ground + 1.62> z`); it **rests on its support** (no floating, no sinking: `--pick` on its base, or a low side view); **collision** makes sense (a trunk blocks, a crown at head height doesn't; walk paths stay ≥ 1 m wide); it casts and receives **shadows** like its neighbours and its materials are lit (no unlit or black-metal look); `--dump-scene` before/after shows only the intended instances; the **licence is recorded** (`ASSETS.md` row + sidecar, `License.txt` copied where the source ships one); triangles and textures within budget.
