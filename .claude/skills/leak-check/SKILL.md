# Leak check

**The rule** (`CLAUDE.md`): after any change to code (C, shaders, build), `build/tools/leakcheck` must end with `leakcheck: OK: zero leaks of ours` before the change counts as done. Map-only edits (including a package's own shaders) skip it; check a changed shader with `glslangValidator` instead (`.claude/skills/lighting-fog-shadows/r3d-pitfalls.md` §4). After larger changes also run `build/tools/leakcheck --asan`.

```bash
./build.sh lsan                 # -O1 -g + LeakSanitizer -> build/linux-lsan/; examples: ./build.sh examples lsan
./build.sh --tools leakcheck    # once: builds build/tools/leakcheck from tools/leakcheck.c (it rebuilds itself when its source changes)
build/tools/leakcheck [--no-build] [--bench] [--asan]   # every main code path under LSan (or ASan + UBSan); exit 1 on a leak
```

It takes about 5 minutes and runs everything in hidden windows (never on the developer's screen). Its test bundles go to its own requests folder, so it doesn't touch the queue. If it prints a leak, fix it before reporting the change as done (or before writing `result.md` for a request).

**Leak check** (`build/tools/leakcheck`, source `tools/leakcheck.c`; options `--no-build`, `--bench`, `--asan`; after every code change, not map-only edits). Builds `build/linux-lsan/monolith` and `examples/build/linux-lsan/` (`./build.sh examples lsan`, which needs a plain `./build.sh` first) when a source is newer (`src/`, `runtime/`, `examples/`, R3D's sources and shaders, and the build itself: `build.sh`, the build program `nob.c` and `src/vendor/nob/nob.h`), then runs every main path in hidden windows or none: the dump modes, shots of the default map (incl. `--shadow-camera --fog-cache`), `tests/models/`, `examples/01_minimal/scene` and `maps/pine_forest`, render scale, `--ao baked` / `--ao-volume` (also across a reload), `--reload-test` both ways and into a broken map, a broken map on the command line, `--shot-hud` with `--select` / `--region`, `--submit` on both maps with the stub terminal, `--export`, `--compile` and compiled maps (dumps, a shot with a reload, a damaged and a stale file, the refused export of the stale one), `--inspect-model`, `--new-map`, `--classify`, every example's `--shot` (the game-style ones load compiled scenes), `run-sh.o` and every program of `build/tools/`, each built with the same sanitizer into the build folder (`build/linux-lsan/run-sh.o`, `build/linux-lsan/tools/`; `--no-build` needs them from an earlier run) and run on harmless inputs only (`request-queue` on a scratch requests folder, `todo` / `ai-todo` `list` in a scratch root, `bench-export-ab --summarize` on hand-made reports, `old-monolith` with bad arguments), and `./build.sh test run_sh` (its table expects the checkout outside `/tmp`: in a worktree under `/tmp` its deletion rows are allowed and fail, harmlessly), and the profiling tool (`tools/profile.c`, built with the same sanitizer into the build folder) on the fixtures in `tests/profile/`. The compiled-map reader's corruption test runs separately under ASan + UBSan: `./build.sh test compiled`. Created bundles, exports and packages go to the trash. Logs: `build/leakcheck/latest/logs/`. `tools/lsan_report.py` ignores a leak only when the frame that **allocated** it is in a driver or system library listed in `tools/lsan.supp` (GL drivers, libglvnd, X11/xcb, D-Bus, the loader); anything allocated in the monolith binary (incl. raylib, GLFW, R3D, assimp: all static) counts. On an NVIDIA machine (driver 615.71) the only ignored leak is NVIDIA's (8 allocations, 366 bytes, context creation); other drivers show other suppressed counts, which is fine as long as "ours" stays 0. `--bench` adds a 10-frame headless bench (opt-in: one benchmark at a time, the `benchmarking` skill); `--asan` also fails on any sanitizer error. GL objects never deleted are not heap leaks, so `Unload*` calls still need review.
