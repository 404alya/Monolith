# Request bundles

What the editor writes into `requests/<YYYY-MM-DD_HHMMSS>_<slug>/` for each request, field by field. The workflow that uses it is the `map-request` skill (`.claude/skills/map-request/SKILL.md`); the code that writes it is `src/launcher.c` (`BuildBundle`, `WriteRequestMd`, `WriteRequestJson`) and `src/import.c`. The bundle has one format number, 9, the only one described here; when the bundle changes, bump `"format"` (in `request.json` and in `request.md`'s first paragraph) and describe the new format.

## Bundle files

| File | Content |
|---|---|
| `request.md` | **Read this first.** The `Model:` line (the model, its tier, who chose it and why), the prompt (verbatim, fenced), the design brief's path, the camera, the crosshair hit, the selection, the screen regions, the sketches, the volumes, nearby groups, a reproduction `--shot` command, and the map path + hash at submit time (for a map with imports also every map-text file with its own hash, below). |
| `request.json` | The same data in machine-readable form, `"format": 9`. Keys: `id`, `slug`, `created`, `instructions`, `resultFile`, `prompt`, `model` (tier, name, reason, override, source, `classifier` = who chose the tier: `ai` / `failed` / `off` / `override`, `classifierModel` = the model that answered or null, `classifierAccount` = the Claude account it ran on (only with a fallback account configured) or null, `seconds` = the classifier's time or null), `camera` (eye, yawDeg, pitchDeg, forward, right, fovyDeg, aspect, width, height), `images` (view, marked, regions, `sketch`: `"sketch.png"` or null), `hit` (kind, index, box, point, normal, distance, line, lineText, group, material, min, max, `rotationDeg` for a turned box, the copy fields below; `model` for models) or `null`, `selection` (per map line: line, lineText, group, `objects`: kind, index, box, the copy fields, material, min/max/center/size, `rotationDeg` for a turned box, `model`), `regions` (below), `sketches` (below), `volumes` (below; each with `snip` and, for a 3D snip, `images`), `nearby` (an object: `center`, `centerIs` `hit`|`eye`, `radius`, `groups` [per group: `group`, `nearest`, `objectsWithinRadius`, `boxesWithinRadius` (same value, older name), `firstLine`, `lastLine` or null, plus `firstMapFile` / `lastMapFile` when that line is in a part]), `selectedCount`, `camera.convention`, `map.hashAlgorithm`, per region also `index`, `rect`, `rectNorm`, `crop`, `grid`, `samples`, `reproduce` (command + argv), `map` (path, package, brief = path of `MAP.md` or `null`, formatVersion, hash, hashAlgorithm, `files`, mtime, version, boxes, models, groups, materials; `files` = every map-text file in the map's file order: `path` (package-relative; the first is the main file), `fullPath`, `bytes`, `hash` (its own FNV-1a 64), `importedBy` (`{ mapFile, line }` of the `import` line that reached it, `null` for the main file)) and `mapReloadedSinceSnapshot`. A model's `model` object: file, position, rotationDeg, scale, origin, translation, collide, shadow, slotMaterials. Copy fields: `nth` (index among the objects of the line, 0-based), `lineObjects` (how many the line made), `repeat` (`counts` of the line's `repeat` prefixes, outer first, the object's `copy` index per repeat, `objectsPerCopy`, `objectInCopy`; `null` without repeats). An object's `kind` is `box`, `model`, `barrier` or `shape`. A `barrier` is an invisible wall (`docs/map-format.md` §2.1 *Barriers*), pointed at or selected only while the developer's barrier overlay was on; its `material` is `null` (`request.md`: "(none: a barrier is invisible)"), `rotationDeg` when its line has `rot`, and its line is edited like a `box` line. A `shape` is an untextured primitive of a `shape <kind> cx y0 cz sx sy sz [rot y p r]` line (`docs/map-format.md`, *Shapes*): wherever it is named (hit, selection, region, sketch and volume objects, edges) it carries a `shape` object `{ kind (cube, sphere, cylinder, cone, capsule, plane), center (its box's centre), size (along its own axes), rotationDeg (as written, 0 0 0 without rot) }` next to its `material` (the `use` active on its line); `min` / `max` are its world bounds; its line takes every edit a `block` line does (y0 = `center` y − size y / 2 when it isn't turned). In `request.md` it shows as `shape #n` with its kind in backticks, and a selected shape line gets a table of kind, centre, size and rotation. |
| `view.png` | The frame exactly as the developer saw it, **without the HUD**, at the window's resolution. |
| `view-marked.png` | The same frame with the **selected objects** tinted and outlined in orange (models: their rotated bounds), the **crosshair hit** shown as a small cyan square with a normal tick, the crosshair drawn at the centre, each **screen region** outlined in magenta with its number, and each **volume** as a green wireframe box (fainter where hidden behind geometry) labelled V1, V2, ... at the middle of its top face. Since format 9 also each **sketch** (a pen stroke) in its colour (red, yellow, blue or white) with its label S1, S2, ... |
| `region-<n>.png` | One per screen region: the crop of `view.png` inside region *n*. |
| `sketch.png` | Only when the developer drew strokes (the pen in snip mode): the strokes alone, with their labels S1, S2, ..., on a transparent background at the size of `view.png`. |
| `snip-<n>-<side>.png` | Per **3D snip** volume V*n* (`volumes[].snip` true): four 1024 × 768 images of **only what is inside the volume**, side `view` (from the developer's camera direction), `front` (from +z, looking along −z), `side` (from +x) and `top` (looking down, −z up in the image); perspective, fovy 40°, framed so the box's bounding sphere fits. Everything outside the box is cut away at its faces (objects crossing a face are cut open there), outside objects still cast their shadows in, the sky is a flat grey and distance and volumetric fog are off. |
| `result.md` | **Written by the session**, last (the `map-request` skill, "result.md"). |
| `state` | The queue state, one line `<state> <time> <writer>`: `queued` (written by the editor), `claimed`, `question`, `done`, `failed`, `cancelled` (written by the coordinator through `build/tools/request-queue`; the editor writes `cancelled` itself for a queued request when no coordinator runs). Not in per-request mode. Never write it yourself. |
| `claim.txt` | The coordinator's fingerprint of the map package and the code at the claim (for recovery after a crash), and the baseline of the map's history (`map-repo`, `base-map` or `base-map-tree`, `base-code`). |
| `map.patch` | Written by `build/tools/request-queue` when the request finishes (never by the session): what the request changed in the package, as `git format-patch --binary` of the request's commit in the package's own repository, paths relative to the package (`no changes` when nothing changed; a plain diff when there is no commit: a package tracked by the main repo, or no git identity). Take it back: `git -C <package> revert <commit>` or `git -C <package> apply -R "$PWD"/requests/<id>/map.patch` (`-C` changes the folder first: an absolute patch path); replay it on another copy of the map at the same starting point: `git -C <copy> am "$PWD"/requests/<id>/map.patch` (a plain diff: `git apply`). docs/request-queue.md §4a. |
| `code.patch` | Only when the code outside `maps/`, `requests/` and `.slop/` changed while the request ran (a code request): that change, repo-relative paths, not committed; `git apply -R requests/<id>/code.patch` in the repo root takes it back. |
| `commit.txt` | The commit (`commit <short sha>`, `none`, `failed: <why>`) and which patches exist; `commit-msg.txt`, `git.log`, `patch-index`, `map-index`: the queue's working files. |
| `cancel` | Written by the editor when the developer cancels the request. |
| `classifier-input.txt`, `classifier.json`, `classifier.log` | The AI classifier's input (the request's context and its text), its answer and its messages, when the classifier ran (docs/request-queue.md, "Models"). Nothing to do for the session. |
| `question.md` | The session's question for the developer, if it has one (the `map-request` skill, "Working under the coordinator"). |

## Details of `request.md`

- **Camera**: the eye position (not the feet), yaw/pitch in degrees, forward and right vectors, fovy 70° (vertical), aspect and resolution.
- **Crosshair hit**: the world point at the screen centre, its face normal (pointing out of the face: axis-aligned for boxes, turned with a turned box, the triangle's normal for models), the distance from the eye, the object (box or model index, min/max; for models also file and transform), its **copy** (`3 of 32 (i = 0, j = 3)`: its index among the objects of its map line, and for a `repeat` line the copy index per repeat, `i` = the first, outer one), its group and material (a model whose every slot has a `material.N` override shows `(all slots overridden: slot 0 = …)`), and the map line, quoted. If the crosshair pointed at the sky it says "Nothing" and `hit` is `null`.
- **Selection**: the selected boxes and models, grouped by source line. Each line's text is quoted once and is followed by a table of the objects it made (index, copy, min, max, centre, size; models: file, position, rotation, scale, origin). One `repeat` line can make dozens of objects. When the selection is only some of them, the user means those copies, not the whole line; the copy column says which (the `map-editing` skill, "Changing one copy of a `repeat` line").
- **Screen regions**: one section per region: its pixel rect in `view.png` (x, y of the top-left corner, width × height, also normalised 0–1), what is under its centre (object, point, normal, distance), the depth range (distance from the eye over the rays that hit something), the sky share; the **edge objects** (what rays a few pixels outside the rect's border hit, nearest first, with the sides they were seen on: what bounds the region); the shares **by map line** (one `repeat` line can be dozens of small objects, so the per-line sum is the useful view); and the objects it shows, each with the **share** of the region's rays that hit it first (largest first; `request.json` has them all: `regions[].objects`, `.lines`, `.edge`, `.center`, `.depth`, `.sky`). The shares come from a regular grid of up to 4096 rays per region, computed at submit time.
- **Sketches** (format 9): one section per stroke `S<n>` the developer drew with the pen in snip mode (**D**), headed with its colour and kind (`### S1 (red arrow)`): its points (count, first, last, in pixels of `view.png`; closed or open), what its **start** and **end** points hit (object, point, normal, distance, or sky), its **world path** (the world points under up to 256 samples evenly spaced along the stroke; `request.md` lists the first and last hit samples and every 32nd one, `request.json` `samples` all of them, `null` where a sample hits the sky), the **objects along it** (what the samples hit, share = fraction of the samples) with their map lines quoted, and for a **closed** stroke (a circle, or a free stroke that ends near its start) its inside analysed like a screen region over the rays inside the outline (rect = the outline's bounds). In `request.json`, `sketches[]`: `index`, `label`, `color` (`red`, `yellow`, `blue`, `white`), `rgb`, `kind` (`free`, `line`, `arrow`, `circle`), `closed`, `points` (`[[x, y], ...]`: a line or arrow is its two end points, the arrow's head at the second; a circle 64 rim points), `start` / `end` (`{ kind, index, point, normal, distance, line, group, material }` or null), `samples`, `objects` (kind, index, line, group, file for models, material, `samples`, `share`, largest first), `lines` (the same per map line) and, when closed, `region` (`rect` plus the keys a region has from `center` on: `center`, `depth`, `samples` = the rays inside the outline, `grid`, `objects`, `sky`, `lines`, `edge`). **How to read them:** a stroke is a gesture over `view.png`. A line or arrow drawn along a surface ("a fence along here", "a path from here") follows its `samples`: build along the world path, not along the 2D line. An arrow points from its start to its end ("slopes down to there", "move this there"): its `start` and `end` hits are the two places. A closed stroke outlines an area ("fill this", "everything in here"): read its `region` as a screen region's. The prompt names strokes by label ("S2") or colour ("the red line").
- **Turned boxes**: a box or block line with `rot yaw pitch roll` (the map-format reference) makes turned boxes. Their min / max / centre / size in the hit line and the tables are their **world bounds** (the AABB of the turned box), not the numbers on the line, which describe the box before it turns. The hit gets a line `- turned: rot y p r`; a selection table of a line with turned boxes gets a last column `rot (yaw pitch roll)` (`-` for a box of that line that isn't turned), and `request.json` gives such a box `"rotationDeg": [yaw, pitch, roll]` (degrees, as written).
- **Volumes**: one section per volume `V<n>`, an axis-aligned box the developer marked in world space (volume mode, **V**, or Shift+V from the selection's bounds). Its `min`, `max`, `center`, `size` (metres, map coordinates) and `cubicMetres`; `snap` (the developer's grid step while marking); `empty` (the share of the volume outside every object's bounds, from a grid of at most 4096 cells, `emptyGrid`: per cell the overlaps of the objects' bounds are summed and capped, so models count by their world AABB and objects that overlap each other count twice; `null` if it could not be computed); `floor` (the first surface straight down from the centre: `y`, `below` = min.y − y, `point`, kind, index, line, group; `null` = nothing below); the **groups** it touches and the shares **by map line**; and the **objects**: every box and model whose world bounds overlap it (a positive overlap on every axis; a flat object only needs to lie within it), largest first, with `shareOfVolume` (overlap / volume), `shareOfObject` (overlap / the object's bounds; flat axes count as 1) and `fullyInside`. `request.json`: `volumes[]` with `index`, `label`, `min`, `max`, `center`, `size`, `cubicMetres`, `snap`, `empty`, `emptyGrid`, `emptyMethod`, `floor`, `objects` (kind, index, box, line, group, file for models, material, shareOfVolume, shareOfObject, fullyInside, min, max; at most 10 000; `objectCount` is how many there are in all), `lines` (per map line: line, lineText, group, kind, objects, fullyInside, shareOfVolume) and `groups` (group, objects, fullyInside, shareOfVolume). Volumes are an editor overlay: they are never in the `.map` file. A **3D snip** volume (marked with **X**, `view-marked.png` labels it `V2 snip` with dashed edges) has a row `3D snip` naming its images; `request.json` `volumes[].snip` is true and `images` lists `{ file, side, camera: { position, target, up, fovyDeg, width, height } }`. **How to read a snip:** the images show the target alone, from four sides, without what stands in front of it; use them to see the shape and arrangement of what the developer means. The object list (`objects`, `lines`, `groups`) is the authority for *which* objects are in it: an object cut by a face shows only its inside part. A face exactly on the box's boundary (a floor the box stands on) shows but may not be listed (zero overlap).
- **Nearby**: the groups that have an object (box or model) within 30 m of the hit point (of the eye if there was no hit), nearest first, with the range of map lines each group covers.
- **Lines in a map with imports** (`docs/map-format.md` §2.10): a line of the main map file is written as its number, as in a map without imports (`line 41`, `### Line 41`, `| 41 |`, `41: <text>`); a line of an imported file is written `<file>:<line>` with the file's package-relative path (`parts/lake.map:41`), everywhere `request.md` names a line (hit, selection, regions, volumes, nearby ranges: `parts/lake.map:3-40`, or `first - last` when a group spans files). In `request.json` every `line` key stays a number, and a line in an imported file gets `"mapFile": "<path>"` next to it (no `mapFile`: the main file). The *Map* section then lists every map-text file (path, bytes, its own FNV-1a 64 at submit, the `import` line that reached it), a command that prints each file's hash, and one that recomputes the combined hash on the "at submit" line: FNV-1a 64 over, for each file in the listed order, its package-relative path, a NUL byte, its size in decimal, a NUL byte and its bytes. Check the hash of each file you will edit, and edit the file that holds the line. A map without imports has only the main file: one hash (the file's own), the single-file command, `map.files` with one entry.
- **Object indices** (`#46`) are positions in the box or model list of the map that was loaded at submit time. They shift when lines are inserted above. The map line and its text are the stable reference.
- A **Warning** line (`mapReloadedSinceSnapshot: true`) means the map reloaded between the selection and the submit, so the indices may not match what the user saw. Locate the target by the coordinates and the quoted line text instead.

**Bundles written before 2026-10-24** tell the session to read `AI-MAP-TOOL.md`. That file is now the `map-request` skill.
