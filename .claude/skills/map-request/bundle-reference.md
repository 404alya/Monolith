# Request bundles

What the game writes into `requests/<YYYY-MM-DD_HHMMSS>_<slug>/` for each request, field by field. The workflow that uses it is the `map-request` skill (`.claude/skills/map-request/SKILL.md`); the code that writes it is `src/launcher.c` (`BuildBundle`, `WriteRequestMd`, `WriteRequestJson`) and `src/import.c`. When the bundle changes, bump `"format"` and keep the older formats described here.

## Bundle files

| File | Content |
|---|---|
| `request.md` | **Read this first.** The `Model:` line, the prompt (verbatim, fenced), the design brief's path, the camera, the crosshair hit, the selection, the screen regions, nearby groups, a reproduction `--shot` command, and the map path + hash at submit time. |
| `request.json` | The same data in machine-readable form, `"format": 2`, `"kind": "edit"` (or `"import"`, the `import-request` skill). Keys: `id`, `slug`, `created`, `instructions`, `resultFile`, `prompt`, `model` (tier, name, reason, override, source), `camera` (eye, yawDeg, pitchDeg, forward, right, fovyDeg, aspect, width, height), `images` (view, marked, regions), `hit` (kind, index, box, point, normal, distance, line, lineText, group, material, min, max, the copy fields below; `model` for models) or `null`, `selection` (per map line: line, lineText, group, `objects`: kind, index, box, the copy fields, material, min/max/center/size, `model`), `regions` (below), `nearby` (an object: `center`, `centerIs` `hit`|`eye`, `radius`, `groups` [per group: `group`, `nearest`, `objectsWithinRadius`, `boxesWithinRadius` (same value, older name), `firstLine`, `lastLine` or null]; import bundles write `[]`), `selectedCount`, `camera.convention`, `map.hashAlgorithm`, per region also `index`, `rect`, `rectNorm`, `crop`, `grid`, `samples`, `omittedObjects`, `omittedShare`; import bundles add `import` {projectDir, mapName, package}, have `camera: null` and no `images`, `reproduce` (command + argv), `map` (path, package, brief = path of `MAP.md` or `null`, formatVersion, hash, mtime, version, boxes, models, groups, materials) and `mapReloadedSinceSnapshot`. A model's `model` object: file, position, rotationDeg, scale, origin, translation, collide, shadow, slotMaterials. Copy fields: `nth` (index among the objects of the line, 0-based), `lineObjects` (how many the line made), `repeat` (`counts` of the line's `repeat` prefixes, outer first, the object's `copy` index per repeat, `objectsPerCopy`, `objectInCopy`; `null` without repeats). |
| `view.png` | The frame exactly as the developer saw it, **without the HUD**, at the window's resolution. |
| `view-marked.png` | The same frame with the **selected objects** tinted and outlined in orange (models: their rotated bounds), the **crosshair hit** shown as a small cyan square with a normal tick, the crosshair drawn at the centre, and each **screen region** outlined in magenta with its number. |
| `region-<n>.png` | One per screen region: the crop of `view.png` inside region *n*. |
| `result.md` | **Written by the session**, last (the `map-request` skill, "result.md"). |
| `state` | The queue state, one line `<state> <time> <writer>`: `queued` (written by the game), `claimed`, `question`, `done`, `failed`, `cancelled` (written by the coordinator through `tools/request-queue.sh`; the game writes `cancelled` itself for a queued request when no coordinator runs). Not in per-request mode. Never write it yourself. |
| `claim.txt` | The coordinator's fingerprint of the map package and the code at the claim (for recovery after a crash). |
| `cancel` | Written by the game when the developer cancels the request. |
| `question.md` | The session's question for the developer, if it has one (the `map-request` skill, "Working under the coordinator"). |

## Format-1 bundles

**Format-1 bundles** (written by game builds before map packages) have no `Model:` line, no design brief, no regions and no models; `request.json` has `"format": 1` and no `kind`, the selection lists `boxes` instead of `objects` and `hit` has `box` but no `kind`. They name the map as `…/maps/monolith.map` (also in the reproduction command), which is now the package `maps/monolith/` (map file `maps/monolith/monolith.map`): use the package path in every command, and read `maps/monolith/MAP.md` anyway. The new file has a header block, so **line numbers and box indices from a format-1 bundle are stale**: locate the target by its coordinates and the quoted line text (as with a hash mismatch: the `map-editing` skill, verification step 1).

## Details of `request.md`

- **Camera**: the eye position (not the feet), yaw/pitch in degrees, forward and right vectors, fovy 70° (vertical), aspect and resolution.
- **Crosshair hit**: the world point at the screen centre, its face normal (pointing out of the face: axis-aligned for boxes, the triangle's normal for models), the distance from the eye, the object (box or model index, min/max; for models also file and transform), its **copy** (`3 of 32 (i = 0, j = 3)`: its index among the objects of its map line, and for a `repeat` line the copy index per repeat, `i` = the first, outer one), its group and material (a model whose every slot has a `material.N` override shows `(all slots overridden: slot 0 = …)`), and the map line, quoted. If the crosshair pointed at the sky it says "Nothing" and `hit` is `null`.
- **Selection**: the selected boxes and models, grouped by source line. Each line's text is quoted once and is followed by a table of the objects it made (index, copy, min, max, centre, size; models: file, position, rotation, scale, origin). One `repeat` line can make dozens of objects. When the selection is only some of them, the user means those copies, not the whole line; the copy column says which (the `map-editing` skill, "Changing one copy of a `repeat` line").
- **Screen regions**: one section per region: its pixel rect in `view.png` (x, y of the top-left corner, width × height, also normalised 0–1), what is under its centre (object, point, normal, distance), the depth range (distance from the eye over the rays that hit something), the sky share; the **edge objects** (what rays a few pixels outside the rect's border hit, nearest first, with the sides they were seen on: what bounds the region); the shares **by map line** (one `repeat` line can be dozens of small objects, so the per-line sum is the useful view); and the objects it shows, each with the **share** of the region's rays that hit it first (largest first; `request.json` has them all: `regions[].objects`, `.lines`, `.edge`, `.center`, `.depth`, `.sky`). The shares come from a regular grid of up to 4096 rays per region, computed at submit time.
- **Nearby**: the groups that have an object (box or model) within 30 m of the hit point (of the eye if there was no hit), nearest first, with the range of map lines each group covers.
- **Object indices** (`#46`) are positions in the box or model list of the map that was loaded at submit time. They shift when lines are inserted above. The map line and its text are the stable reference.
- A **Warning** line (`mapReloadedSinceSnapshot: true`) means the map reloaded between the selection and the submit, so the indices may not match what the user saw. Locate the target by the coordinates and the quoted line text instead.

**Bundles written before 2026-10-24** tell the session to read `AI-MAP-TOOL.md` (and, for imports, its section "Import requests"). That file is now the `map-request` skill (imports: the `import-request` skill).
