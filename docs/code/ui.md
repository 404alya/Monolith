# `src/ui.c`: the editor UI toolkit

The editor's UI: the Outfit font and Pixelify Sans for titles, the type scale, colour tokens and the helpers every editor overlay draws with. The look is described in [ui-design.md](../ui-design.md).

## Fonts

Outfit and Pixelify Sans are both under the SIL Open Font License 1.1 (`resources/fonts/`). They are compiled in from `src/font_outfit.h` and `src/font_pixelify.h`, generated by `tools/embed_font.py`, so nothing is read from disk.

## One atlas, one batch

Every size of the type scale in both weights is rasterised once (bitmap glyphs at the exact pixel size they are drawn at: sharper than one scaled SDF font at 14-24 px, and no shader) and packed into ONE atlas texture, which also holds a white block that becomes raylib's shapes texture. Text and rectangles then share a texture, so the whole overlay stays in one batch instead of flushing at every switch between a panel and its text (it is drawn every frame, also over a reused frame that otherwise costs ~0.2 ms).

Text is drawn at integer positions and the native size, so the bilinear filter samples texel centres.

## Shapes from the atlas

- **Rounded corners** come from the same atlas (anti-aliased discs and rings, drawn as nine-slices). raylib's `DrawRectangleRounded*` emit dozens of triangles each and switch the batch's draw mode, which made the overlay cost ~0.13 ms more per frame (measured with ~60 key caps on screen).
- **Key caps**, the most frequent shape, are one baked sprite per line size (border and fill in one), drawn as a 3-slice: 3 quads per cap instead of ~15.
- **A panel's soft halo** is one baked sprite drawn as 8 quads around it (a CSS box-shadow without a blur pass).

## Text layout

Text is laid out here, the way raylib's `DrawTextEx` / `MeasureTextEx` do it, but with a codepoint → glyph table instead of raylib's `GetGlyphIndex`, a linear search over the ~290 glyphs for every character (0.04-0.05 ms per frame of the HUD); the quads are the same.
